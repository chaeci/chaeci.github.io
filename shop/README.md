# MONO ATELIER — 의류 쇼핑몰 프로토타입

프론트엔드만으로 완결되는 모던 컨템포러리 의류 쇼핑몰입니다.
모든 데이터는 **정규화된 21종 테이블(JSON — 단일 레지스트리 `STORE_TABLES`)** 로 관리되고 브라우저 `localStorage`에 저장되며,
`data/schema.sql`(SQLite **21개 테이블** — `users`·`categories`·`products`·`product_images`·`product_variants`·`cart_items`·`orders`·`order_items`·`order_claims`·`coupons`·`coupon_targets`·`product_reviews`·**`product_qnas`**·**`review_votes`**·`point_policies`·`point_logs`·`faqs`·`sms_logs`·`dispatch_logs`·`site_settings`·`help_topics`)로 **1:1 이식**할 수 있게 설계했습니다.
관리자 **데이터 관리 > 테이블 현황**과 **JSON 다운로드(`tables`)** 가 같은 레지스트리를 읽어 테이블 수·건수가 항상 일치합니다(v1.9.9).

## 3. 데이터 구조 (SQLite 이식 대비)

```
users ─┬─< orders ─┬─< order_items >─ product_variants >─ products ─┬─< product_images
       │           └─< order_claims (order_id UNIQUE)              └── free_shipping_threshold
       └─< cart_items >────────────────┘
orders.coupon_code ───────────────< coupons (code UNIQUE) ─< coupon_targets >─ users
```

| 테이블 | 컬럼 | 비고 |
| --- | --- | --- |
| `users` | id, email, password_hash, name, phone, address, **postcode**, role, **grade**, **points**, created_at | role: customer/admin · grade: NORMAL/SILVER/GOLD/VIP · points = 보유 포인트(1P=1원) |

* `total_amount` = 상품금액 합계 + `shipping_fee` − `discount_amount` (전 건 검증됨).
* `free_shipping_threshold`: `NULL` = 스토어 기본 100,000원, `0` = 무조건 무료배송, `N` = 해당 상품 합계 N원 이상 무료배송.
* `products.badge`: 프리셋(`BEST`/`NEW`/`SALE`/`LIMITED`) 또는 관리자가 입력한 16자 이내 문구. `NULL` = 뱃지 없음.
* `products.model_info`: 모델 키·체중·착용 사이즈 문구(60자 이내). `NULL`/빈 값이면 상세에서 「모델 정보」 항목을 그리지 않습니다. 시드 13개 상품 모두 값이 있습니다(잡화는 `모델 172cm 착용 컷`).
* `coupons.target_user_ids`: `[]` = 전체 공용. 값이 있으면 그 회원만 목록 노출·코드 적용이 가능하고 다른 계정은 `이 계정에 발급된 쿠폰이 아닙니다.`로 거부됩니다. SQLite에서는 `coupon_targets` 행으로 전개됩니다.
* `coupons.target_grades`: `[]` = 등급 제한 없음. `['GOLD','VIP']` 처럼 지정하면 그 등급 회원에게만 노출·적용됩니다(회원 지정과 동시에 쓰면 합집합). 관리자 화면에서는 `전체 공용 / 회원 등급별 / 특정 회원 지정` 3모드로 고릅니다.
* `users.grade`: 시드 데모 회원은 `GOLD`, 관리자 계정은 `NORMAL`. 신규 가입은 `NORMAL`. 마이페이지 프로필과 관리자 주문/회원 목록에 등급 배지가 표시됩니다.
* 시드 규모: users 5(관리자 1·데모 회원 4) · categories 5(사이즈 코드 포함) · products 13(판매중 12, 숨김 1, 제품번호 MA-0001~MA-0013) · product_images 39 · product_variants 88 · orders 16(배송완료 12 포함 — v1.9.6 월별 추이용 6~9월 주문 4건 o_013~o_016 추가) · order_items 17 · order_claims 2(무료 1 + 유료 1) · coupons 3(공용 2 + 전용 1) · coupon_targets 1 · product_reviews 9(코트 7건 = 5개씩 페이징 확인) · point_policies 4 · point_logs 4 · faqs 8 · sms_logs 1 · **dispatch_logs 3(SMS 1 + 이메일 2, 차단 1)** · site_settings 1 · help_topics 4.
* `order_claims.shipping_fee`: `defect`·`wrong_item` = **0원**, `change_of_mind`·`size_color` = 반품 **3,000원** / 교환 **6,000원**(왕복). 무료 접수는 `payment_status='free'`, 유료 접수는 토스 결제 후 `'paid'` + `payment_key`.
* `order_claims.stock_restored`: 반품을 `완료`로 바꿀 때 재고 복구를 **한 번만** 하기 위한 플래그(0/1).
* 교환/반품 신청 가능 단계는 **배송중(`shipping`)·배송완료(`delivered`)** 이고, 배송 전 주문은 `주문 취소`로 처리합니다. 시드의 `o_001`(배송완료·접수 이력 없음)에 데모 계정으로 로그인하면 바로 신청 버튼을 눌러볼 수 있습니다.
* 비밀번호는 데모용 `sha256('mono-atelier$' + password)` 해시로 저장합니다(앱 내 동기 SHA-256 구현, 시드와 동일 값 검증 완료).

### SQLite로 옮길 때

1. `data/schema.sql` 실행 (`PRAGMA foreign_keys = ON` 포함, FK·CHECK·SKU UNIQUE·뷰 4종).
2. `data/schema-seed.json`(또는 앱의 **JSON 다운로드**)을 테이블별로 `INSERT`.
   금액은 정수, 시각은 ISO-8601 TEXT, `is_active`는 0/1로 변환하면 그대로 들어갑니다.
   `coupons.target_user_ids`(배열)는 `coupon_targets` 테이블의 행으로 전개합니다.
3. `v_product_stock`, `v_order_summary`, `v_coupon_targets`, `v_order_claims` 뷰로 상품별 재고·주문 합계·전용 쿠폰 발급 대상·교환/반품 접수 현황을 바로 검수할 수 있습니다.

**교환 / 반품 신청 (v1.5)**
- 마이페이지 주문 내역(배송중·배송완료)에서 **「교환/반품 신청」** → 모달에서 ① 유형(반품/교환) ② 사유 ③ 교환 희망 옵션·상세 사유 입력

- **무료 접수**: 버튼「무료 교환/반품 접수」→ 즉시 `order_claims` 생성(`shipping_fee=0`, `payment_status='free'`, `status='requested'`) + 토스트
- **유료 접수**: 버튼「배송비 3,000원(6,000원) 결제 후 접수」→ **토스페이먼츠 SDK v2 결제창** (`pending_claim` 을 localStorage 에 저장 → `?tossClaim=success` 복귀 시 신청번호·금액 검증 → 접수, 실패/금액 변조 시 미접수). `file://`·오프라인은 데모 결제로 접수
- 접수된 주문은 `반품 접수됨 (무료)` · `교환 접수됨 (배송비 6,000원 결제)` 배지와 진행 상태(`접수됨`/`수거중/승인`/`완료`/`반려`)를 보여주고 **중복 신청을 차단**합니다
- 사유·유형을 바꿔도 입력한 상세 사유·희망 옵션이 유지됩니다(모달 전체 재렌더 없이 배지·배송비·버튼만 갱신)

**상품 상세 / 갤러리 (v1.2 · v1.3 · v1.6)**

- **모델 정보**: 상세 정보 표의 첫 줄에 `모델 정보 — 모델 174cm · 54kg · M 사이즈 착용` 처럼 표시(`products.model_info`, 관리자 입력·수정, 비우면 숨김)

**이미지 전체 화면 확대 — 라이트박스 (v1.6)**
- 상세 대표 이미지를 **탭(클릭)** 하거나 이미지 우측 상단 **「확대」 버튼**을 누르면 전체 화면 뷰어가 열립니다
- 원본 비율(`object-fit: contain`)로 화면을 채우고, **이미지 탭 = 1x ↔ 2x 토글**, **`+`/`−` = 1x~3x**, **`원본`** 리셋, **드래그 이동**, **두 손가락 핀치 줌**(`touch-action: none` + 포인터 2개 좌표 비율), **`‹` `›`·방향키로 같은 상품의 다른 컷 전환**
- **`✕` · Esc · 브라우저 뒤로가기** 로 뷰어만 닫히고 상세 모달·옵션 선택은 그대로 유지됩니다(히스토리 한 겹 추가)
- 뷰어가 열려 있는 동안 배경 스크롤을 잠그고, 상단 컷 번호(`2 / 3`)·현재 줌(`2x`)을 표시

**상품 뱃지 관리 (v1.3)**

**사진 파일 업로드 (v1.3)**
- 관리자 상품 등록/수정에서 **📷 사진 업로드** 버튼(`<input type="file" accept="image/*" multiple>`)으로 **실제 사진 파일**을 올려 대표 이미지·갤러리(최대 6장)로 사용

**할인 쿠폰 / 배송비 (v1.2 · v1.3)**

| 항목 | 값 |
| --- | --- |

**정책**
- 재고 차감·복구는 변이 시점에 즉시 반영되며, 취소는 `paid`/`preparing`에서만 가능(배송 시작 후 차단).
- 교환/반품은 **배송중·배송완료** 주문만 신청할 수 있고 **한 주문당 1건**(`order_claims.order_id UNIQUE`)만 접수됩니다. 반품을 `완료`로 바꿀 때만 재고가 복구되고 중복 복구되지 않습니다(교환은 재고 변동 없음).
- FAQ 카테고리는 `site_settings.faq_categories` 코드 목록으로 관리하며(시드 6종), FAQ 카드·게시판 필터가 이 목록을 그대로 씁니다. FAQ가 연결된 카테고리는 삭제되지 않고, 이름을 바꾸면 그 카테고리를 쓰던 FAQ도 함께 옮겨집니다(v1.9.5).
- 리뷰는 **배송완료 + 구매확정(`confirmed_at`)** 된 주문항목에만 작성할 수 있고, 관리자가 **반려·포인트 회수**하면 **딱 1번 재작성**할 수 있습니다(2차마저 반려되면 최종 차단). 포토·영상 포인트는 반려 시 회수되고 재작성 시 1회 다시 지급되어 **주문항목당 최대 2회**를 넘지 않습니다.
- 관리자가 옵션을 삭제해도 과거 주문이 참조하는 옵션은 재고 0으로 보존(주문 스냅샷 무결성 유지).
- 쿠폰은 활성 상태·만료일·최소 주문금액을 **계산 시점마다** 검사하고, 결제 시 주문에 `coupon_code`/`discount_amount` 스냅샷을 남깁니다(이후 쿠폰을 중지해도 과거 주문 금액은 그대로).
- 배송비는 **선택된 상품군 합계**로 판정하며 한 주문에 3,000원 1회만 부과합니다.
- **기간 매출·월별 추이의 매출은 「취소 제외 실매출」**(`total_amount` 합계, 취소 주문 제외)입니다. 조회 기간은 주문일(`created_at`)의 **브라우저 로컬 날짜** 기준이며 시작일·종료일을 모두 포함합니다(시작일 > 종료일이면 안내 토스트만 띄우고 결과는 비웁니다).
- 이전 버전(v1.1)에서 만든 `localStorage` 데이터는 v1.2 스키마로 **자동 마이그레이션**됩니다(갤러리·쿠폰 시드·무료배송 기본값 보충).
- localStorage를 쓸 수 없는 환경에서는 메모리로 동작하며 안내 토스트를 표시합니다.

## 6. 참고

- 상품 이미지는 `images` CLI로 생성한 AI 스튜디오 컷 13종 + 그 크롭인 디테일 컷 24종(webp)입니다. 실제 브랜드·상품과 무관합니다.
- 결제는 **토스페이먼츠 테스트 키**로 열리는 테스트 결제창이며 실제 청구가 발생하지 않습니다. 카드 정보는 토스페이먼츠 결제창에서만 입력되고 이 앱은 저장하지 않습니다.
- 공개 저장소 배포본에는 실명·연락처·실주소가 들어가지 않습니다(예시값 `홍길동` / `010-0000-0000` / `서울특별시 송파구 올림픽로 300`). `build.py` 가 빌드 시 개인정보를 검사합니다.
- 이 앱은 프론트엔드 완결형 프로토타입입니다. 서버·동시성 제어는 없으므로 실제 운영 시 재고 차감은 DB 트랜잭션(예: `UPDATE ... WHERE stock >= ?`)으로 옮겨야 합니다.
